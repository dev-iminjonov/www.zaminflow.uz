# Defect Report: QA-003

**Title:** Duplicate `<h1>` Headings on Main Landing Page (Violates WCAG 2.2 SC 1.3.1)  
**Defect Type:** Accessibility Defect / Semantic HTML Hierarchy  
**Severity:** S2 Major  
**Priority:** P1  
**Status:** New  
**Area:** Public Landing Page / Assistive Technology  
**Route:** `/`  
**Components:** [`frontend/src/app/page.tsx`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/app/page.tsx#L173), [`frontend/src/components/ActiveTradeMetrics.tsx`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/components/ActiveTradeMetrics.tsx#L200)  

---

### Preconditions
User navigates to the root landing page `http://localhost:3000/`. Screen reader (NVDA / VoiceOver) or heading inspection tool active.

---

### Steps to Reproduce
1. Open Chrome DevTools and inspect document headings:
   ```javascript
   document.querySelectorAll('h1')
   ```
2. Observe the returned NodeList.

---

### Expected Result (WCAG 2.2 SC 1.3.1 Info & Relationships)
A single document should contain exactly **one** `<h1>` representing the primary topic of the page (in this case: *"Connecting smallholder farmers with commercial buyers"*). Subsequent major sections such as Active Trade Metrics should use `<h2>`.

---

### Actual Result
Two `<h1>` elements are present in the DOM:
1. `h1` in Hero: `Connecting smallholder farmers with commercial buyers` (line 173 of `page.tsx`)
2. `h1` in Stats section: `Active Trade Metrics` (line 200 of `ActiveTradeMetrics.tsx`)

This creates a split document outline, causing screen readers to misidentify the page structure.

---

### Reproducibility
100% reproducible on desktop and mobile viewports.

---

### Suggested Fix
Update [`ActiveTradeMetrics.tsx`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/components/ActiveTradeMetrics.tsx#L200) to accept a `headingLevel?: "h1" | "h2"` prop defaulting to `"h2"` when embedded inside [`page.tsx`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/app/page.tsx):
```tsx
const HeadingTag = headingLevel === "h1" ? "h1" : "h2";
return (
  <HeadingTag className="text-4xl sm:text-[56px] leading-[1.05] font-extrabold tracking-[-0.03em] select-none">
    <span className="text-[#087a3c]">Active</span>{" "}
    <span className="text-[#17352c] dark:text-white">Trade Metrics</span>
  </HeadingTag>
);
```

---

### Acceptance Criteria for Re-Test
1. `document.querySelectorAll('h1').length === 1` on the root page `/`.
2. Heading hierarchy reads logically: `h1` (Hero) $\rightarrow$ `h2` (Our Team) $\rightarrow$ `h2` (Active Trade Metrics).
