# Defect Report: QA-001

**Title:** Public Sign-Up Endpoint Fallback Accepts `role=ADMIN` (Returns HTTP 201 Instead of HTTP 403)  
**Defect Type:** Security Defect / Authorization Bypass  
**Severity:** S1 Critical  
**Priority:** P0 (Must fix immediately before release)  
**Status:** New  
**Area:** Authentication / RBAC  
**Route / Endpoint:** `POST /api/v1/auth/sign-up`  
**Environment:** `http://localhost:3000`, Next.js 15, FastAPI, Docker container `dairy_frontend`  

---

### Preconditions
User is unauthenticated. Postman, cURL, or a Python script is used to transmit an HTTP request directly to the API endpoint.

---

### Steps to Reproduce
1. Send an HTTP POST request to `http://localhost:3000/api/v1/auth/sign-up` with the following JSON payload:
   ```json
   {
     "role": "ADMIN",
     "full_name": "Unauthorized Operator",
     "organization_name": "Malicious Corp",
     "phone_number": "+998 90 999 88 77",
     "email": "injected_admin@zaminflow.uz",
     "password": "Password123!",
     "accepted_terms": true
   }
   ```
2. Observe the HTTP status code and response body.

---

### Expected Result (per SRS Section 2.2 & Rule 2)
The request must be strictly rejected with **`HTTP 403 Forbidden`**:
```json
{
  "detail": "Admin accounts cannot be created via public sign-up"
}
```
No account or session cookies should be generated.

---

### Actual Result
The endpoint responds with **`HTTP 201 Created`** and sets authentication cookies:
```json
{
  "status": "created",
  "user_id": "user-1794052345678",
  "organization_id": "org-1794052345678",
  "email": "injected_admin@zaminflow.uz",
  "role": "FARMER",
  "canonical_role": "farmer",
  "dashboard_path": "/dashboard/farmer",
  "kyb_status": "INCOMPLETE",
  "access_token": "zf-token-farmer-..."
}
```

---

### Reproducibility
**3 of 3 attempts (100% reproducible).** Tested via Python integration runner and cURL.

---

### Evidence
Execution log from container:
```bash
docker exec dairy_backend python -c "import urllib.request, json
req = urllib.request.Request('http://frontend:3000/api/v1/auth/sign-up', data=json.dumps({'role':'ADMIN','full_name':'Hacker','email':'hacker@zaminflow.uz','password':'Password123!','accepted_terms':True}).encode(), headers={'Content-Type':'application/json'})
resp = urllib.request.urlopen(req)
print('STATUS:', resp.status)"
# Output: STATUS: 201
```

---

### Impact
Violates the core security requirement: *"Admin accounts are NEVER selectable or creatable on the public sign-up page. The server must reject role=admin from public sign-up"*. While the fallback downgraded the user's role to `FARMER`, accepting invalid administrative registrations gives attackers a foothold and masks backend policy enforcement.

---

### Likely Cause
In [`frontend/src/app/api/[...path]/route.ts`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/app/api/[...path]/route.ts#L123), `tryProxy` proxies to the FastAPI backend, which correctly returns `HTTP 403 Forbidden`. However, `tryProxy` only forwards responses if status is 200, 201, or 409:
```typescript
if (proxied && (proxied.status === 200 || proxied.status === 201 || proxied.status === 409)) {
  return proxied;
}
```
Because status was 403, it fell through to the Next.js local fallback, which lacked a guard rejecting `"ADMIN"`.

---

### Suggested Fix
In [`frontend/src/app/api/[...path]/route.ts`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/app/api/[...path]/route.ts):
```diff
--- a/frontend/src/app/api/[...path]/route.ts
+++ b/frontend/src/app/api/[...path]/route.ts

@@ -192,6 +192,12 @@ export async function POST(req: NextRequest, { params }: { params: Promise<{ pa
```

### Acceptance Criteria for Re-Test
1. Sending `POST /api/v1/auth/sign-up` with `{"role": "ADMIN"}` returns `HTTP 403 Forbidden`.
2. Response body contains `{ "detail": "Admin accounts cannot be created via public sign-up" }`.
3. No user record, session token, or cookie is created.
