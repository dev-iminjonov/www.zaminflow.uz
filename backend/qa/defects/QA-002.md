# Defect Report: QA-002

**Title:** Potential Open Redirect Vulnerability via `?next=` Parameter for Admin Role in `SignInCard`  
**Defect Type:** Security Defect / Open Redirect (OWASP A01:2021)  
**Severity:** S2 Major  
**Priority:** P1  
**Status:** New  
**Area:** Authentication / Routing  
**Route / Component:** `/signin?next=...`, [`frontend/src/components/auth/SignInCard.tsx`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/components/auth/SignInCard.tsx#L82), [`frontend/src/lib/roles.ts`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/lib/roles.ts#L115)  

---

### Preconditions
User is unauthenticated and opens a crafted sign-in URL with an external redirect target.

---

### Steps to Reproduce
1. In a web browser, navigate to:
   `http://localhost:3000/signin?next=https://attacker-controlled-site.com`
2. Authenticate as an administrator:
   - Identifier: `admin@zaminflow.uz`
   - Password: supplied locally through `SEED_ADMIN_PASSWORD`
3. Click **Sign in →**.

---

### Expected Result
The application must validate that the `next` target is a relative internal path belonging to the application (e.g. must start with `/dashboard` or `/` without leading double slashes `//`). External URLs must be rejected, and the user must land safely on `/dashboard/admin`.

---

### Actual Result
In [`frontend/src/lib/roles.ts`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/lib/roles.ts#L115), `isPathAllowedForRole(nextParam, "admin")` evaluates line 115:
```typescript
if (roleKey === "admin") return true;
```
Because it unconditionally returns `true` for administrators without validating whether `nextParam` is an external URL, the client-side router attempts navigation to `https://attacker-controlled-site.com`, facilitating spear-phishing attacks targeted at platform operators.

---

### Reproducibility
Code review & manual execution: 3 of 3 attempts.

---

### Impact
Admins can be tricked via phishing links into logging in and being silently redirected to an attacker's clone site, harvesting credentials or active session context.

---

### Suggested Fix
In [`frontend/src/lib/roles.ts`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/lib/roles.ts):
```diff
--- a/frontend/src/lib/roles.ts
+++ b/frontend/src/lib/roles.ts
@@ -110,6 +110,10 @@ export function getDashboardPathForRole(roleKey: RoleKey): string {
 export function isPathAllowedForRole(path: string, roleKey: RoleKey): boolean {
   const config = ROLES[roleKey];
   if (!config) return false;
+  
+  // Guard against Open Redirects: must start with / and not // or protocol
+  if (!path.startsWith("/") || path.startsWith("//") || path.includes("://")) {
+    return false;
+  }
 
   // Admin has access to all dashboards
   if (roleKey === "admin") return true;
```

---

### Acceptance Criteria for Re-Test
1. Navigating to `/signin?next=https://evil.com` and signing in as Admin redirects strictly to `/dashboard/admin`.
2. Navigating to `/signin?next=//evil.com` redirects strictly to `/dashboard/admin`.
3. Valid internal paths such as `/signin?next=/dashboard/admin/disputes` continue to redirect to `/dashboard/admin/disputes`.
