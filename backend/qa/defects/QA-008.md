# Defect Report: QA-008

**Title:** Nav Item "Live statistics" Has Static Hardcoded Active Border Irrespective of Scroll Position  
**Defect Type:** Design Deviation / UX Navigation Defect  
**Severity:** S3 Minor  
**Priority:** P2  
**Status:** New  
**Area:** Public Navigation / Landing Page  
**Route:** `/`  
**Component:** [`frontend/src/app/page.tsx`](file:///c:/Users/Muhammad%20Aziz/Downloads/www.zaminflow.uz/frontend/src/app/page.tsx#L120)  

---

### Preconditions
User is on the main landing page `http://localhost:3000/` scrolled to the top (Hero / Our Company section).

---

### Steps to Reproduce
1. Load `http://localhost:3000/`.
2. Inspect the floating top navigation bar.
3. Observe the four links: "Our Company", "Our Team", "Live statistics", "Contact us".
4. Scroll up and down between the Hero section and the Team carousel.

---

### Expected Result
The active indicator (green text `#087a3c` and `border-b-2 border-[#22d36b]`) should reflect the user's current viewport section (scroll-spy):
- When at the top: "Our Company" is active.
- When scrolled to `#team`: "Our Team" is active.
- When scrolled to `#stats`: "Live statistics" is active.

---

### Actual Result
"Live statistics" has a hardcoded static class:
```tsx
<a
  href="#stats"
  className="text-[#087a3c] border-b-2 border-[#22d36b] pb-0.5 transition font-bold"
>
  Live statistics
</a>
```
Even when the user is reading the Hero or Team section, the navigation permanently indicates that the user is on "Live statistics", confusing page orientation.

---

### Suggested Fix
Implement an `IntersectionObserver` scroll-spy hook or track `window.scrollY` to dynamically assign the active class to the currently visible section (`#company`, `#team`, `#stats`, `#contact`).

---

### Acceptance Criteria for Re-Test
1. At top of page, "Our Company" has the active border indicator.
2. Scrolling past `#team` transfers the active indicator to "Our Team".
3. Reaching `#stats` activates "Live statistics".
